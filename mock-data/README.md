# Chico mock 投资数据集

> **全部为合成数据。** 价格、财报、持仓、评级没有一条是真实市场记录，任何数字都不得用于真实投资决策，也不得对外展示为行情。真实性只体现在一处：量级与分布对齐了 2026 年 8 月可公开检索到的观测值，来源逐条记录在 [`data/sources.json`](data/sources.json)。

面向 Chico 投资工作台开发的替身数据：11 个标的（6 只个股 + 5 只基金）、4 条基准指数、每个标的 500 个交易日（2024-07-24 至 2026-08-14），覆盖行情、估值、财务、一致预期、资金筹码、公司行动、风险绩效、基金档案与持仓、事件流。

## 用法

```sh
node mock-data/generate.mjs     # 重新生成 data/ 下全部文件；无依赖，Node 22+
node mock-data/verify.mjs       # 校验下文列出的全部不变量，不成立则非零退出
```

生成是确定性的：同一份 `anchors.mjs` 在任何机器上重跑产出逐字节相同的 JSON。因此数据可以进版本库、可以进快照测试，也可以在两个分支之间做有意义的 diff。

```ts
import type { Quote, PriceHistoryFile } from './mock-data/types.d.ts'

const quotes: { quotes: Quote[] } = JSON.parse(readFileSync('mock-data/data/quotes.json', 'utf8'))
const bars: PriceHistoryFile = JSON.parse(readFileSync('mock-data/data/bars/SSE-600519.json', 'utf8'))
```

[`types.d.ts`](types.d.ts) 描述每个文件的结构，不依赖仓库里任何包，可以整份复制进消费方。

## 专业投资者的数据需求

以下是一个投资工作台要支撑「看懂一只标的并做出决策」所需的数据域。**覆盖**列标注本数据集的状态。

### 第一层：没有它就无法开始

| 数据域 | 关键字段 | 为什么必需 | 覆盖 |
|---|---|---|---|
| 标的识别 | 场所、代码、名称、板块、上市日、涨跌幅限制、最小交易单位、股本结构 | 决定标的能不能交易、按什么规则交易；代码在两个场所是两个标的 | 完整 |
| 日线行情 | 开高低收、成交量额、涨跌幅、振幅、换手率 | 走势图、技术指标、流动性判断的唯一来源 | 完整，500 日 |
| 最新快照 | 现价、前收、涨跌幅、涨跌停价、52 周高低、总市值与流通市值 | 自选列表与标的页首屏 | 完整 |
| 复权口径 | 复权因子及其变化点 | 不做复权，任何跨越除权日的收益率、均线、回测都是错的 | 完整 |
| 交易日历 | 场所休市日 | 决定「昨天」是哪一天，决定序列有没有缺口 | 近似（见局限） |

### 第二层：决定判断质量

| 数据域 | 关键字段 | 为什么必需 | 覆盖 |
|---|---|---|---|
| 估值 | PE-TTM / PE 静态 / PB / PS / PCF / EV-EBITDA / 股息率 / 分红率 | 贵不贵是相对判断，单看价格没有意义 | 完整 |
| 估值历史分位 | 当前值在自身历史中的百分位、历史区间 | 「17 倍 PE」只有对上「处于近两年 5% 分位」才构成信息 | 完整，500 日窗口 |
| 财务 | 三张表主要科目、单季与累计、同比、**披露日** | 基本面判断的根基；披露日决定这份报表从哪天起对市场可见 | 完整，11 个报告期 |
| 财务比率 | 毛利率、净利率、ROE、ROIC、资产负债率、研发占比、自由现金流 | 盈利质量与再投资能力 | 完整 |
| 银行专用科目 | 净息差、不良率、拨备覆盖率、核心一级资本充足率、成本收入比、AUM | 银行没有营业成本与存货，通用模板会给出无意义的读数 | 完整（600036） |
| 一致预期 | 覆盖机构数、评级分布、目标价、未来三年预测、近三月调整方向 | 市场预期的位置；预期差本身就是交易线索 | 完整 |
| 风险绩效 | 区间收益、年化波动、最大回撤及区间、夏普、索提诺、卡玛、VaR、Beta、相关系数 | 组合层面的取舍必须在风险调整后进行 | 完整，全部由序列实测 |
| **总收益口径** | 含股息总收益、股息贡献、相对基准超额 | 高股息标的的价格收益与持有收益每年可差数个百分点 | 完整 |

### 第三层：解释「为什么涨跌」

| 数据域 | 关键字段 | 为什么必需 | 覆盖 |
|---|---|---|---|
| 资金流 | 主力净流入、四档单量、北向/南向持股及变动 | 短期价格的直接推动力 | 完整 |
| 杠杆与做空 | 两融余额及占比（A 股）、淡仓（港股） | 情绪极值与潜在的强平压力 | 完整 |
| 筹码结构 | 股东户数及环比、机构持股比例、前十大股东及增减持 | 筹码集中还是分散 | 完整 |
| 供给事件 | 限售解禁时间表及占流通盘比例 | 可预见的供给冲击 | 完整 |
| 公司行动 | 分红（登记日/除权日/派息日）、送转、回购 | 直接改变持股数与成本，且驱动复权 | 完整 |
| 事件流 | 日期、类别、标题、方向、重要性 | 把价格异动对上原因 | 完整，每标的 10+ 条 |

### 基金专属

| 数据域 | 关键字段 | 为什么必需 | 覆盖 |
|---|---|---|---|
| 净值序列 | 单位净值、累计净值、日涨跌幅 | 场外基金没有 K 线，净值是唯一的价格 | 完整，500 日 |
| 场内价格 | 收盘价、IOPV、折溢价率 | 场内买卖的成本与净值不同，折价套利是真实策略 | 完整（ETF/LOF） |
| 货币基金口径 | 七日年化、每万份收益 | 净值恒为 1，涨跌幅口径完全不适用 | 完整（000198） |
| 规模与份额 | 各报告期资产净值与份额 | 规模影响策略容量；急剧变化是风险信号 | 完整，4 个报告期 |
| 费率 | 管理费、托管费、销售服务费、申赎费 | 直接侵蚀长期收益 | 完整 |
| 基金经理 | 姓名、任职起始、任职回报、在管规模与只数 | 主动基金买的是人；换人是重估事件 | 完整（005827 为双经理） |
| 业绩基准 | 基准表述、跟踪指数、跟踪误差 | 超额收益必须相对基准定义 | 完整 |
| 持仓 | 前十大重仓及权重、行业配置、资产配置、集中度、换手率、**披露日** | 理解风格与风险敞口；持仓按报告期滞后披露 | 完整（货币基金除外） |
| 同类排名 | 各区间排名/同类总数 | 绝对收益无法判断优劣 | 完整 |

### 尚未覆盖

按对工作台的价值排序，这些是下一批该补的：分钟级与盘口数据（日内交易与流动性成本）；债券与可转债要素（到期收益率、久期、转股价值）；宏观与行业时序（利率、PMI、产量价格）；供应链与股权关系图谱；ESG 与合规名单；期权隐含波动率。

## 数据满足的不变量

这些性质是数据可信的原因，也是替换成其他生成方式时必须保持的：

- **末值锚定**：每条价格与净值序列的最后一根等于 `anchors.mjs` 里的真实观测收盘价。
- **两年收益锚定**：`return2Y` 落在**含息总收益**上；不复权价格涨幅 = 总收益 − 股息贡献，两者在 `risk-metrics.json` 中分列。
- **涨跌停**：没有任何一天的收盘涨跌幅突破该板块限制（主板 10%、创业板与科创板 20%、港股无限制）。
- **K 线自洽**：`low ≤ min(open, close) ≤ max(open, close) ≤ high`，成交量与成交额恒为正。
- **52 周区间**：近 250 日的最高最低价校准到真实观测的 52 周区间附近。
- **Beta 成立**：个股收益由基准收益与独立冲击合成，按 `Beta = ρ · σ标的 / σ基准` 反解相关系数，实测 Beta 落在目标值 ±0.25 内。
- **指标可推导**：风险指标、估值分位全部由本数据集的序列算出，改序列则指标随之改变，不存在独立填入的孤立数字。
- **披露日守恒**：财务与基金持仓都带 `disclosedOn`，PE-TTM 的滚动窗口只使用观察日之前已披露的报告期。

`verify.mjs` 逐条检查以上性质。它独立于生成器：换掉生成方式、换掉锚点、接入真实数据源之后它都应该继续通过，通不过说明新数据在某个下游会依赖的地方与旧数据行为不同。

## 与 `ctx.marketData` 的关系

现有的 [`dsh-market-data`](../packages/investment/market-data/README.md) seam 只覆盖价格：`search`、`quote`、`priceHistory`。本数据集的行情部分是它的超集——多出换手率、成交额、涨跌停价、复权因子，这些是 A 股工作台必须显示而 seam 目前没有的。

其余数据域在现有代码里**没有任何对应物**，因此这份数据集同时是未来 seam 的需求输入。落地时至少需要四个独立的能力接缝，而不是往 `marketData` 上堆字段：估值与财务（读报告期、带披露日）、一致预期（读卖方预测）、资金与筹码（读持仓与流向）、基金（读净值、档案与持仓）。它们的提供方各不相同、更新频率各不相同、失败语义也各不相同。

另有两处现有类型需要扩展才能表达本数据集：`Market` 是闭合联合且不含场外基金，而 005827 与 000198 没有挂牌场所；`Quote` 没有涨跌停价与换手率字段。

## 已知局限

- **交易日历是近似的。** 节假日按 2024–2026 的法定安排给出，港股只跟随内地的春节、国庆首日与元旦。存在个别本该休市的日子出现了交易，反之亦然。真实日历需要场所日历源。
- **锚点精度参差。** 收盘价、基金规模、基金经理、费率来自可检索的公开页面；财务量级、股本、行业分类部分为估计值。恒生指数点位未取得当日观测。逐条状态见 `sources.json`。
- **财务是按年度总量拆分出来的**，不是真实报表。科目之间满足基本勾稽（毛利=营收−成本、自由现金流=经营现金流−资本开支），但资产负债表不完整、不做严格平衡。例外是茅台 2026 上半年：累计归母净利锚定在检索到的真实值 445 亿，因此它的 2026 年度是由半年报反推的下滑年，而不是按增长率外推。
- **一致预期与筹码结构为构造值。** 目标价与评级分布对齐了检索到的真实数字（如茅台 23 家覆盖、均值 1722.27），但机构名称、股东名单是通用占位。
- **没有停牌、涨跌停一字板、退市、配股。** 序列连续无缺口，缺少这些真实边界情形。
- **基金持仓只有一个报告期。** 无法做持仓变动归因。
- **事件流不驱动价格。** 事件日期与价格异动没有因果对齐，只是同一时间轴上的两组数据。

## 换成真实数据源

改 `anchors.mjs` 重跑即可——生成逻辑不含任何标的专有分支。要接入真实数据，实现顺序建议为：先用真实 `quote` 与 `priceHistory` 替换行情（现有 seam 已能承载），再补估值与财务（新 seam），最后是基金。在每一步完成之前，对应的域仍可从本数据集读取，界面不必等待数据源就绪。
