# Agent Note：价格序列的图表座位，以及 Chico 的工作台图表

Status: implemented

[English](2026-08-16-price-series-chart-seat.md) | 中文

## Problem

出厂的价格序列卡片只画蜡烛，别的什么都没有：没有坐标轴，没有十字光标，没有成交量，没有指标。读者能看到形状，却无法说出某根蜡烛是哪一天、价格落在什么位置，也无法判断一次异动是否有成交量支撑。Chico 是投资工作台，它的用户需要的是交易平台给他们的那张图。

把出厂图表直接改成那张图并不可行。同一张卡片会在每一种组合里渲染，包括关于代码库的对话——在那里，指标副图和逐日读数是噪声。所以工作台图表只能触及投资工作，而其他地方的 harness 图表必须原样不动。

两条既有约束排除了显而易见的路线。`tool.call.toolview` 支持按 key 接管某个工具的整行，但接管是组合级且静态的，而且行的外壳不能被产品包 import——client bundle purity 明确禁止。读取当前 frame 同样行不通：`ctx.layout` 只暴露写操作，三个列占位者之外的任何东西都无法得知当前 mode。

## Decision

**price-series 行为图表本身声明一个子插槽。** `tool.call.priceSeries`（`single`，session 作用域）接收派生出的 `model` 和工具自己的 `bars`。无人占座时该行绘制 `PriceSeriesBlock`，因此任何不注册的组合都逐字保持出厂图表。这个座位只替换绘制、保留图标与摘要与展开——正是这一点让产品包无需触碰它不许 import 的行外壳就能贡献一张图。

**决定座位内容的是行，不是外壳。** `ToolRow.priceSeries` 从图表模型改为一个已渲染的节点。行外壳不再知道什么是价格序列，而 price-series 行成为在出厂图表与座位占位者之间做选择的唯一位置。

**原始 bars 与派生模型一同传递。** `priceSeriesCardModel` 现在返回 `{ model, bars }`。派生几何把价格归一化进单位盒并丢弃蜡烛用不到的字段，成交量首当其冲；否则要画成交量副图的占位者只能重新索取一份它刚刚已经拿到的序列。ui-primitives 的 `PriceSeriesBar` 补上了数据里一直存在的 `volume` 字段——两个真实调用方读到的 bar 都带它，`dsh-tools` 更是一直将其列为必填。

**占座与否按对话判断，而不是按组合判断。** `dsh-client-ui-watchlist` 为整个 Chico 组合占下该座位，而它的占位者只在对话绑定到某只标的时绘制工作台图表，否则回退到 `PriceSeriesBlock`。判据是绑定关系而非当前 frame：对话在创建时绑定且永不改判，因此读者切换 frame 不会改变一段对话里图表的形态，挂载 Chico 也不会改变一段关于代码库的对话里价格序列的样子。

**指标在整条序列上计算，之后才切片。** 若在可见窗口上计算，每次预热都会从左边缘重新开始，同一个交易日的 MA60 会随缩放程度而不同。参数沿用境内行情软件的出厂设置（MA 5/10/20/60，MACD 12/26/9 且柱状图乘 2，KDJ 9/3/3 以 50 为种子），因为改动参数会让每个读数都无法与 Chico 用户已经在读的平台对照。

**图表按实测像素宽度绘制。** `ResizeObserver` 提供真实容器宽度，SVG 与之 1:1 映射，取代了出厂卡片被拉伸的 `preserveAspectRatio="none"` viewBox——在那种画法下，蜡烛比例和标签字号会随容器变化。

## Alternatives considered

**由 Chico 的包接管 `market_history` 的 `tool.call.toolview`。** 因两点被否决：接管是组合级的、没有按对话的粒度；而且占位者将不得不重画行外壳，这正是 client bundle purity 禁止产品包 import 的东西。

**给 `ctx.layout` 增加 mode 读取接口，并按当前 frame 键控图表。** 被否决，因为它既是更大的改动，也是更差的规则。它会为一个消费者拓宽 layout 服务；而按实时 frame 键控会让一段对话的图表在读者切换列时变形——绑定判据恰好避开了这一点。

**给 `PriceSeriesBlock` 加一个 `variant` 属性，让 Chico 传 "pro"。** 被否决，因为这会把投资领域的关注点——指标周期、副图切换、市场配色习惯——塞进一个通用组合同样会渲染的共享 primitive，此后该 primitive 的任何消费者都无法独立演进。

**把图表抽成新的 `ui-chico-chart` 包。** 是推迟而非否决。今天这张图只有一个属主、包内两个调用点；此时划包只是没有第二个消费者的装配动作。`products/chico/` 仍将 `packages/client/ui-chico-*` 记录为将来需要时的归宿。

## Consequences

在一段关于已关注标的的对话里，`market_history` 调用会画出蜡烛、MA5/10/20/60、可切换的 成交量/MACD/KDJ 副图、两侧坐标轴，以及一个逐日给出开高低收、副图数值与各条均线的十字光标读数；方向键可移动光标，标题价格是 `<output>`，因此数值变化会被播报而不是无声改变。名称档案面板无条件绘制同一张图——那一栏本就只在打开某只标的时存在。其他任何对话，无论在 Chico 还是在其他组合中，渲染结果与改动前完全一致。

`ToolRow` 的 `priceSeries` 属性从模型变成节点，这对任何曾传入模型的行都是源码级改动；实际上只有 price-series 行如此。`ui-watchlist` 为该插槽声明新增了对 `ui-tool` 的纯类型依赖，与它已有的 `ui-conversation`、`ui-layout` 依赖是同一种安排。

已知缺口记录在两个包的 README 中：图表提供五个预设区间，既不能缩放也不能平移；绑定到尚未打开的标的的对话仍绘制出厂蜡烛图，因为占座判断读的是当前打开标的的对话列表；副图只有三个指标，没有主图叠加线，两者都无法配置。
