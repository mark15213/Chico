# Agent Note: 行情接缝背后的真实数据源

Status: implemented

[English](2026-08-15-tushare-market-data-provider.md) | 中文

## Problem

Chico 随附的行情提供方只有一个，而它是 fixture：三个写死的标的，加上一条锚定在固定日期的闭式价格序列。接缝、工具、自选投影和工作台都已建成且正确，而它们展示的每一个数字都是编造的。用户询问有哪些股票接口，选定了 Tushare Pro，并排除了盘中行情——一个用来阅读和记录论点的工作台需要的是收盘后数据。

有两件 fixture 从未触及的事挡在真实提供方前面。

**`available()` 答不出来。** 接缝每次调用都查询它，好让失去权限的提供方停止被选中，而它被声明为 `(): boolean`。任何真实的答案都是一次凭据查询，而那是异步的。同步的提供方只能映射一个缓存标志，靠订阅 `credentials/updated` 刷新——而这恰恰是每次查询这一设计要避免的陈旧映射，并且它在启动时与第一个请求相竞争。

**没有任何错误码表示"本提供方够不到那个交易场所"。** `MarketDataErrorCode` 有一个表示交易场所未列出该代码的拒绝，还有四个关于提供方选择的，但没有一个适用于服务上海却不服务香港的来源。

## Decision

### `available()` 返回 promise，且候选者被并发询问

签名现在是 `available(): Promise<boolean>`，`resolveProvider()` 变为异步。未配置 id 时它同时询问每一个已注册的提供方而不是依次询问，因此选择的开销是一轮查询而不是每个提供方一轮——可用性现在是 I/O，而调用方没有选择的名册不应该成倍放大它的延迟。

影响面是五个文件，这正是现在动手的理由：这个接口是在唯一实现还是一张恒返回 `true` 的表格时写下的。

### `MARKET_DATA_VENUE_UNSUPPORTED`，归在请求一侧

服务部分交易场所的提供方以这个错误码拒绝其余的。它与针对单次请求的拒绝归在一起，而不是与 `PROVIDER_*` 选择失败归在一起，因为提供方被正确地选中，也正确地拒绝了一个标的——于是 `WatchlistService.degrade` 让那一行没有价格并保留列表其余部分，而这正是一只港股在内地数据源上应有的结果。

### 提供方覆盖内地交易所，收盘后

`dsh-market-data-tushare` 通过 Tushare 单一的 POST 端点读取 `stock_basic`、`daily`，以及可选的 `adj_factor`。其中有四个决定无法从 API 本身看出。

**单位在边界处一次性换算。** `daily` 以手报告成交量，因此乘以 100 以得到接缝承诺的股数。`previousClose` 和 `changePercent` 取自交易场所的 `pre_close` 和 `pct_chg` 而不是重新计算，因此它们与交易场所公布的一致。

**`session` 恒为 `closed`，`asOf` 是交易场所的收盘时刻。** Tushare 为一个交易日标注日期但不标注时刻。报告墙钟时间，或者在交易时段内猜测 `open`，会让读者以为一个陈旧的收盘价是实时价。

**复权是配置项，默认关闭。** `adj_factor` 位于比 K 线更高的 Tushare 积分门槛之后。默认为 `backward` 会让所有只拥有 K 线的账号失效，因此 `adjustment` 默认为 `none`，由有权限的账号主动开启。两个方向按它们移动的对象命名——`backward` 复权到今天的基准（前复权），`forward` 复权到第一根 K 线的基准（后复权）——代码里写明了这一点，因为这两个名字与中文习惯相反。

**名册是单飞的。** Tushare 没有检索端点，因此 `search` 在完整的上市名册上本地匹配，而 `quote` 读取它以获得显示名称。自选列表会同时为每一行定价，因此没有共享的 inflight 的话，第一次打开就会为每个关注标的各下载一次名册。这次共享抓取刻意不响应任何单个调用方的 `AbortSignal`——中止它会让等在同一个 promise 上的每个读者一起被取消——而是由单次调用的时间预算来限制它。被拒绝的抓取会清空 inflight 槽位，否则之后的每一次读取都会去等一个已经失败的 promise。

### Chico bundle 移除 fixture

`market-data-fixture` 移出 `chico-web-app`，`market-data-tushare` 移入。bundle 自己的注释早已写下这一步：*不能把合成价格当作真实价格呈现的部署，应在加入数据源时禁用该行。* 没有 token 时提供方报告自己不可用，没有提供方可被选中，每一次读取都以 `MARKET_DATA_PROVIDER_UNAVAILABLE` 失败——这是响亮且可操作的失败，而不是在一个无法为任何标的定价的组合之上画出一列横杠。

token 是凭据引用（`TUSHARE_TOKEN`），绝不以取值形式出现在随包文件里，每次操作都通过 base bundle 挂载的凭据接缝解析。

## Alternatives considered

**保持 `available()` 同步并缓存凭据答案。** 否决：这个缓存要求每个带凭据的提供方都订阅 `credentials/updated`，而且它仍然会在初次探测完成之前与第一个请求相竞争。改为异步把修复一次性放进接缝，而不是永远放进每一个实现里。

**无条件返回 `true`，让 token 失败在请求时暴露。** 在 Tushare 是唯一提供方时可行，一旦有两个就失效：fixture 恒为可用，因此同时持有两者的组合会判定选择有歧义，而不是选中已配置的数据源。

**bundle 里同时随附两个提供方并把 `provider` 固定为 `tushare`。** 否决：fixture 会成为产品组合里的无用负担，而缺少 token 时会报告 `CONFIGURED_UNAVAILABLE`——那是一条关于固定 id 的消息，而不是关于读者真正需要提供的 token 的消息。

**用 `MARKET_DATA_UNKNOWN_INSTRUMENT` 表示够不到的交易场所。** 作为谎言被否决：00700.HK 是上市的，告诉读者他们的代码不存在会让他们去找一个并不存在的拼写错误。

**读取 `trade_cal` 来确定历史窗口。** 推迟。窗口是启发式的——每个交易日 1.75 个自然日加 14 天下限——接缝允许这一点，因为提供方可以返回比请求更少的交易日。读取日历意味着每次历史请求多一次调用，而该启发式目前还没有丢失过一根 K 线。

## Consequences

自选、工作台和工具没有任何改动。它们读的是接缝，而获得真实实现的正是接缝——这是先建能力接缝的回报。

Chico 现在需要先配置才能展示任何东西。这是首次运行体验上的真实倒退，也是正确的取舍：另一种选择是一个把编造的收盘价当作交易场所自身数据呈现的工作台。

`market-data-fixture` 保留它的职责。它服务于包测试和无密钥重放，在那里，输出随墙钟时间变化的提供方撑不起可重放的快照。

基金仍然够不到。`Market` 是一个交易所的闭集，`Quote` 描述的是成交价，因此开放式基金两者都放不进去。服务它们是一个接缝层面的决定，必须先于提供方能承载它们而发生。

## Testing

`packages/investment/market-data-tushare/tests` 针对一个被打桩的端点覆盖该提供方，语句、分支和函数均达 100%：它发送什么、列数组解码、每一条拒绝路径（带原因和不带原因的非零 code、非 200、传输故障、自身超时、调用方自己的取消被原样交回、四种畸形响应体）、单位换算、无论服务端返回何种顺序都取到最新交易日、名册的单飞与 TTL 以及拒绝之后被清空的槽位、两个复权方向与三种复权被拒绝的方式、不花费调用即拒绝交易场所，以及无需重启的 token 重读。

`packages/bundle/chico-web-app/tests` 在打桩的凭据面之上启动随包的行组，并断言两种结果：已配置 token 时通过真实接缝取回报价，缺少 token 时响亮拒绝。它同时断言该组合不随附合成提供方，也不携带 token 取值。

`packages/investment/market-data/tests` 和 `packages/investment/watchlist/tests` 在它们的提供方替身里承接了异步的 `available()`。
