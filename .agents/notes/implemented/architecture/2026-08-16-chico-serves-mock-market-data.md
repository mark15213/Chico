# Agent Note: Chico serves mock market data

Status: implemented

English | [中文](2026-08-16-chico-serves-mock-market-data.zh.md)

## Problem

Chico's composition read prices from Tushare, and the dependency made the product unusable in exactly the situations where its surface was being built. Three failures were observed in one session against a working token and a reachable network:

- The model issued `market_quote` and `market_history` concurrently. Three HTTP requests hit Tushare at once — `quote` reads the roster in addition to the bars — and one returned `TypeError: fetch failed`. The provider has no retry, so the quote failed while the history beside it succeeded.
- The watchlist reads a quote per followed name, so the same class of failure left the left column spinning on "Reading the watchlist…" past ninety seconds, and later showed "No quote" in the record panel.
- None of that describes the workbench. It describes a network.

The composition's own README argued the opposite position — that a workbench must never present invented closes as a venue's own, and that `dsh-market-data-fixture` was therefore deliberately excluded. That argument is right for a deployment whose readers act on prices, and wrong for the only deployments this composition currently has, which exist to build and demonstrate the surface.

## Decision

**The Chico composition serves synthetic prices, and says so.** The patch layer's feed row is now `@deepseek-ai/dsh-market-data-mock`, which answers from a dataset compiled into the package with no credential and no network. The composition README, the package README, and the provider's module documentation all open by stating that every price is synthetic.

**A new provider package rather than the existing fixture.** `dsh-market-data-fixture` computes a closed-form sine series over three instruments; its determinism backs keyless snapshots whose expected outputs are recorded against exactly those values. Rewriting it to serve a different dataset would have rewritten those snapshots for reasons unrelated to what they cover.

**The dataset is compiled into the package, not read from the repository.** `src/dataset.ts` is generated by `scripts/build-dataset.mjs` from `mock-data/data/` and committed. A published package cannot reach a directory that exists only in this checkout, and reading JSON at runtime would make the provider's answers depend on a path outside its own tree. Columns rather than an array of bar objects: the same 500 sessions cost about a third as much source text.

**Ten instruments, chosen by what the seam can address.** Six equities and four benchmark indices. The source dataset's two off-exchange funds are skipped because `Market` is a closed union with no member for a fund that trades on no venue — the seam has no address for them, and inventing one would be a change to the seam made for a fixture's convenience.

**`disabled: true` removes the provider from selection.** A composition that mounts it by accident then fails with `MARKET_DATA_PROVIDER_UNAVAILABLE` rather than presenting invented closes as a venue's own.

**Tushare stays in the workspace.** It is a working provider for a deployment that wants live prices; swapping the row back is the whole change, because `market-data` pins no `provider` and selection resolves to the single usable one.

## Alternatives considered

**Add retry and caching to the Tushare provider.** Rejected as the wrong problem to solve first. Retries would have made the observed failure rarer without making the surface reproducible, and a workbench being built still could not be demonstrated offline, screenshotted deterministically, or replayed. The provider's missing retry remains a real gap for any deployment that swaps the row back, and is recorded in its own README rather than fixed here.

**Mount the existing fixture provider.** Rejected: three instruments on a sine series produce charts with no realistic shape, and the package's determinism is load-bearing for existing snapshots.

**Read `mock-data/data/` at runtime through a configured path.** Rejected because it makes a package's answers depend on a directory outside its own tree, and because the path does not exist in a published install.

**Keep Tushare and let the surface degrade.** Rejected on the evidence: a watchlist that spins for ninety seconds and a record panel that says "No quote" are not a degraded surface, they are an absent one.

## Consequences

Chico now boots and runs with no market-data credential and no network reachability. The watchlist populates immediately, every chart draws, and the same prices appear on every machine and every run — which is what makes the surface demonstrable and its screenshots comparable.

Every price the composition shows is invented. **Nothing in the current surface marks a price as synthetic at the point of display**: `Quote` and `PriceBar` carry no provenance field, so a chart drawn from this provider is visually identical to one drawn from a venue. The composition's README and the provider's README both say so, and a surface-level marker — a badge on the quote, or a provenance field on the seam — is the obvious follow-up if this composition is ever shown to someone who might act on the numbers.

The dataset ends on a fixed anchor date (2026-08-14) and never advances, so a surface comparing it against the wall clock reports a series that ages with the checkout.

The bundle's composition test changed shape with the decision: the assertion that no synthetic provider ships is now the assertion that the mock feed does and that no live feed sits beside it, and the real-composition boot test runs with no `fetch` stub at all — a call that reached the network would fail the test, which is the property being asserted.
