# Agent Note: 行情能力接缝

Status: implemented

[English](2026-08-15-market-data-capability-seam.md) | 中文

## Problem

Chico 工作台需要价格：侧栏行需要关注标的的最新报价，图表需要它最近的日频 K 线。Harness 中没有任何东西能连接交易场所，而可能提供数据的来源在权限、覆盖范围、复权约定和许可条款上各不相同。

把某个场所的客户端直接写进工具，会把产品钉死在一个来源上，第一个需要更换数据源的部署就得重写该工具。价格还携带两个容易丢失、丢失代价又很高的事实：观测**发生在什么时候**，以及某个历史价格**已经包含了哪种公司行动复权**。把复权后的 K 线与拆股前记录的价格作比较的消费方，会得到一个没有任何报错的错误答案。

## Decision

`ctx.marketData` 是一条带两个操作（`quote` 和 `priceHistory`）的能力接缝，其下是按名称注册的提供方注册表。在问题相同之处，它完全沿用 [web 接缝](2026-06-24-web-capability-seam.md)——按 id 注册、拒绝重复、执行时选择且不依赖注册顺序、每次调用查询 `available()`——只在行情确有不同之处才偏离。

### 时间和复权属于取值本身，而不是某种约定

`Quote.asOf` 是交易场所为该标的定价的事件时间。它不是请求时间，也不是渲染时间，JSDoc 明确写出这一点，因为这三者经常被混为一谈，而只有其中一个能让陈旧性判断成立。`Quote.session` 报告该时刻交易场所是否开市，这正是"因为闭市所以没动"与"本该在动却没动"之间的分界。

`PriceBar.date` 是交易日而非时间戳，因为一根 K 线覆盖一个交易日。`PriceHistory.adjustment` 是结果上的必填字段（三个成员：`none`、`backward`、`forward`），而不是带默认值的请求选项：把 K 线与已记录价格作比较的调用方必须知道自己拿到的是什么，而默认值会让某一种悄悄到来。

### 标的身份是一个组合，不是不透明 id

`InstrumentRef` 是 `{ market, symbol }`。仓库对不透明的跨边界 id 施加品牌类型，而这里刻意不是：两半对每个消费方都有意义，提供方解析的正是这个组合。`Market` 是封闭联合，因为结算日历、涨跌幅限制和交易单位因场所而异，所以消费方在已知成员上分支，而不是解析自由字符串。

### 拒绝优于截断

`maxHistorySessions`（默认 500）限定单次提供方调用。更大的 `sessions` 请求抛出 `MARKET_DATA_HISTORY_RANGE_REFUSED`，且不会到达提供方。截断会让请求五年的调用方用一年的 K 线渲染出一张标着五年的图——一个看起来正确的错误答案，正是产品承受不起的失败类型。

`maxSearchMatches`（默认 20）是同一条规则用在检索上，拒绝的理由也相同：请求五十条匹配却画出二十条的调用方，会把一份被截断的列表当成完整答案呈现。

### 检索是身份解析，而提供方可能没有这个能力

用户知道名字的时候远多于知道交易场所和代码的时候，因此 `search` 进入了接缝，而不是留给消费方自己解决：没有它，自选表只能由已经知道 `SZSE:300750` 是什么的人来填。

`InstrumentMatch` 只携带标的与名称，别无其他。一次顺带定价的检索会让每一次击键都为大多数匹配用不到的数据付费，而需要价格的调用方本来就有 `quote`。

数据源没有检索端点的提供方会以 `MARKET_DATA_SEARCH_UNSUPPORTED` 拒绝，而不是解析出空列表。空结果与无能力的来源会把消费方引向相反的结论——"这个名字不存在"对"去别处问"——因此它们不能共用一种表示。该方法在提供方接口上是必需而非可选的，理由相同：缺失的方法会让每个消费方都去探测它是否存在。

## Alternatives considered

**用一个 `prices` 操作同时返回最新值和历史。** 否决：二者成本不同、新鲜度要求不同、缓存生命周期也不同。自选列表的一行需要每个标的每隔一段时间取一次报价；一张图只需要一次性取很多根 K 线。把它们合并会让每次报价都为没人索取的 K 线付费。

**扩展 `ctx.web` 而不是新建接缝。** 否决：web 提供方回答的是"抓取这个 URL"和"搜索这个查询"。行情提供方用领域词汇回答领域问题，并且有自己的权限模型。共用同一个服务会迫使两类独立配置的能力共用同一套选择策略。

**把 `adjustment` 做成带默认值的请求选项。** 否决：默认值恰恰是消费方在两种基准上比较价格而毫无察觉的成因。把它作为结果上的必填项，等于把事实放在错误会发生的地方。

**给 `InstrumentRef` 加品牌类型。** 否决：品牌规则针对的是调用方不得读取内部结构的 id。这里两半都属于契约——界面展示 symbol，策略在 market 上分支。

**把超限的历史请求截断到上限。** 否决，理由见上文决策。

## Consequences

接缝随包发布时没有任何提供方，因此在提供方包注册之前，`ctx.marketData` 会抛出 `MARKET_DATA_PROVIDER_UNAVAILABLE`。对于先于首个数据源落地的接缝，这是预期状态，选择相关的测试把它当作一等结果覆盖，而不是当作缺口。

只有价格。公司行动、指数成分和基本面都不在其中；把它们作为可选字段加进来，会产出一个顶着一个名字的多重能力服务。每一项都应在真有能力需要时拥有自己的接缝。

没有缓存也没有限流：循环轮询的消费方每次都会到达提供方。二者目前都属于提供方或组合层；把任一项加进接缝，都会让新鲜度变成接缝的属性而不是观测值的属性，与上文关于 `asOf` 的决策相矛盾。

## Testing

`tests/market-data.spec.ts` 覆盖注册、重复拒绝、释放、全部选择分支（自动、歧义、配置缺失、配置不可用、无可用）、signal 转发，以及两个上限的边界与越界情形——包括被拒绝的请求不会到达提供方。`market-data-fixture/tests` 覆盖按代码前缀、按名称子串、按交易场所的匹配、调用方 limit，以及空查询不列出整张表而是什么都不返回。
