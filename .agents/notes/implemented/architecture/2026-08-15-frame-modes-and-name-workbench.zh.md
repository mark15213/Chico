# Agent Note: 框架模式与个股工作台

Status: implemented

[English](2026-08-15-frame-modes-and-name-workbench.md) | 中文

## Problem

自选原本作为对话视图环里的一个页签发布，与对话、轨迹并列。那个位置说的是"这是当前会话的另一种视图"，而自选不是：它在每个会话里都是同一本账，并且在完全没有打开会话时也应该存在。

位置决定了从属。页签是对话的下级，因此这份列表永远只能是它的附属品——而实际的工作方式是反过来的。**专业用户从一只标的开始，对话是关于那只标的的。**

产品设计要求一个三栏工作台：左栏关注的标的，中栏那只标的的对话，右栏那只标的的决策链路。harness 本来就有三栏。它没有的是让这三栏的占用方一起变化的任何机制。

## Decision

### 框架是一个模式，由布局持有

`ctx.layout` 新增了 `mode`（默认 `sessions`）和 `setMode`。侧边栏和详情栏都读它，因此两栏绝不会描述不同的东西。切换框架时顺带关闭详情面板：它的占用方随模式变化，让它保持打开会在一个正在看别的东西的读者眼皮底下替换面板内容。

模式放在布局 store 而不是任何一栏里，因为它是关于**框架**的事实。一个由侧边栏持有、只移动侧边栏的切换器，会重复页签当初犯的同一个错误。

### 侧边栏的区域变成框架列表

`sidebar.workspaces`（单例）变成了 `sidebar.mode`（列表）。每个条目拥有从切换器到底部的整个区域，并携带选中它的那个切换项。`ui-workspace` 把会话浏览器注册为 `sessions`；工作台把标的列注册为 `names`。

外壳为每个注册画一个切换项，并且只渲染当前激活的那一个。只注册了一个框架时不画切换器——没有可选的东西时，切换器是什么都没解释的装饰。导轨上也不画：56px 里每个控件只有一个图标的位置，放不下一排标签。

### 详情栏变成按框架作键

`details`（单例）变成了 `keyed`，以模式为键。`ui-conversation` 把工具检查器注册在 `sessions` 下；工作台把记录面板注册在 `names` 下。

这终于回答了工作台设计留下的那个开放问题：*个股档案是与工具检查器共享详情栏，还是其中一个搬走？* 都不是。它们不在同一个框架里，因此从来不会争夺同一个座位。一个看起来像冲突的问题，其实是缺了一个区分。

### 打开一只标的，要连它落到的那一栏一起打开

标的框架每次打开一只标的时都会请求布局展开记录栏。记录面板可以自行收起而不清除选择；选择或重新选择一只标的会再次展开它。一个不把自身结果呈现出来的选择不算导航，而把宽度还给对话也不能丢掉读者的位置。

会话门槛也随之调整。详情栏原本以"存在且非 blank 的会话"为前提，这对 harness 自己的详情是对的——它是某次对话里的一次调用——但对一只标的是错的：标的比任何会话都活得久，并且在第一个会话打开之前就已经存在。该门槛现在只作用于默认框架。

### 打开一只标的，会把对话导航到这只标的自己的对话

中栏属于 `ui-conversation`，因此工作台不渲染它——工作台**导航**它。打开一只标的会读取记录、选中这只标的最近的一次对话，没有对话时则开一个新的。打开的标的在左栏展开它自己的对话列表，因此可以直接挑一个更早的。

**一只标的下的对话不属于任何工作区。** 当读者的工作单元是一个项目时，工作区流程是正确的入口；但在一只标的下面，它挡在读者和他关于这只股票要说的第一句话之间。`ISessions` 为此增加了 `startAt(cwd)`：用 `cwd` 且不带 `workspaceId` 开一个对话。工作台传入 [followed-names](../../../../packages/investment/followed-names/README.md) 的归档目录，经由 `watchlist.archive()` 读取，因此产出的文件落在一个持久的地方，而只是随手看了一眼的标的不会留下一个目录。备选方案是为每只标的注册一个工作区，那会为每一次随手一瞥都在磁盘上建一个目录。

去掉那次调用并不足以去掉工作区，而在对话不再空白的那一刻绑定，把一只标的的对话归到了另一只名下。[对话开场归框架所有](2026-08-15-frame-owned-conversation-opening.md)取代了这两点：携带工作区前置条件的正是开场本身，而对话为一只标的而创建，并在创建时绑定。

### 工作台拥有两栏和两个可观察对象

这批行和打开的标的既不是会话作用域也不是 root 作用域：它们是一本账和一个选择，在每个会话里都相同。槽位的 `store` 句柄只承载一个作用域，而这两个槽位并不共享同一个，因此插件持有这两个值，并把同一份订阅交给两栏。在左栏打开一只标的会带动右栏；关注一只标的会让两栏之下的列表一起变化。

### 标的可以在被关注之前打开

搜索结果直接打开。记录不依赖关注标志——那是[标的记录](../../../../docs/subsystems/name-record.md)自己的决定——因此"我先看看"是成立的，而关注仍然是一个独立的、有意为之的动作。

## Alternatives considered

**保留视图环里的自选页签，并在旁边加上记录。** 否决：这保留了让那个位置成为错误的从属关系。页签是被移除的，不是被补充的。

**直接接管 `details` 单例槽位。** 否决：这会为所有使用 Chico bundle 的用户删掉工具检查，只为给一个框架一栏——而它只在那个框架激活时才需要。

**由 `ui-sidebar` 独自持有 `mode`。** 否决：详情栏必须随它更换。一个只移动一栏的切换器会让两栏描述不同的东西——这恰恰是页签位置的那个失败。

**把记录渲染进中栏、放在对话下面。** 否决：记录是**对照着**对话读的，不是读完之后再读的。两栏正是要点所在。

**为每只关注的标的注册一个工作区。** 否决：它复用了已有的分组方式，但会为用户只是瞥了一眼的标的在磁盘上建一个目录。标的本身已经是工作单元；归档目录才是它的对话该跑的地方。

**标的列按涨跌幅、或按市场决定的任何东西排序。** 否决：这一列会在两次瞥视之间自行重排。关注顺序是用户建立这份列表的顺序，而且它天然稳定。

## Consequences

五个共享包发生了变化：`ui-layout`（模式状态与服务）、`ui-sidebar`（框架列表取代区域槽位）、`ui-workspace`（浏览器改为注册为一个框架）、`ui-conversation`（检查器以 `sessions` 为键），以及 `runtime`（`ISessions.startAt`）。它们都不知道任何与投资有关的事；每一个只知道框架的占用方不止一个，以及一次对话可以在工作区之外开始。

这个框架的标签是"投资"，而不是它打开时那份列表的名字。读者进入的是围绕一只标的的一种工作方式，而关注列表只是它的第一栏。

绑定是单向的。标的能列出它的对话；对话不知道自己属于哪只标的，因此从会话框架打开的对话不会显示它属于哪个标的。

侧边栏的固定列表槽位被移除了。它是两次提交之前为这个想法的一个更窄版本建的，而框架列表吸收了它的全部角色——一个没有消费方的扩展点，只会让下一个读者产生疑问。

没有任何东西从对话中提取链路条目，因此实际上全部由用户自己写。设计里展示的那个回执——"已记入决策链路，撤销"——属于产生它的那次提取。

## Testing

`packages/client/ui-layout/tests` 覆盖 store 里的模式，包括切换会关闭详情面板、以及重选当前框架不动它，还有服务转发及其未接线时的响亮失败。

`packages/client/ui-watchlist/tests` 覆盖纯推导；标的框架（行、待验证标记及其缺席、打开一只标的、空状态、导轨上的沉默、报不出价的行）及其检索（去空白的查询与上限、空输入框不发请求、不关注就打开一条匹配、按请求关注、已关注标记）；记录面板（未选标的的状态、数字与图、两次读取、收起时不清除焦点、空链路的说明、条目的日期与来源、校准数字、会话链接、只对打开的判断提供结清、结清发送的结论、按所选种类手写的条目、被拒绝的空条目、图读不出时仍可读的记录、失败的读取）；两个可观察对象；以及两个注册的展开／收起转发与 fiber 拆卸证明移除。

`packages/client/runtime/tests` 覆盖 `startAt`：每次调用都会创建携带 `cwd` 且不带 `workspaceId` 的会话；按标的复用空白会话属于工作台，它只读取该标的已绑定的对话。

`packages/investment/watchlist/tests` 覆盖 `archive` 报告注册表自己的目录。

`packages/bundle/chico-web-app/tests` 断言发布的 patch 插入了记录与工作台那一行。
