# Agent Note: 自选投影与标签页

Status: implemented

[English](2026-08-15-watchlist-projection-and-tab.md) | 中文

## Problem

[关注标的注册表](../../../../docs/subsystems/followed-names.md)带着持久记录、测试和文档发布了，却没有任何途径能够到达它。没有东西列出已关注的标的，没有东西去关注一只，也没有工具把它摆在模型面前——能力存在，产品没有变化。

一行自选是"名字挨着价格"，这同时需要注册表和[行情接缝](2026-08-15-market-data-capability-seam.md)。两者互不拥有：记录必须挺过一次提供方更换，而提供方服务的消费方里也有从未听说过自选表的。于是这个连接无处安放，而把它放到任何一边都会成为两者之间的第一条依赖。

无论如何，浏览器读不到其中任何一个。客户端 bundle 无法引入 Node 服务，因此任何界面都得先有一条 Remote。

## Decision

### 连接是一个消费方包，不是第三个接缝

`packages/investment/watchlist` 注入 `followedNames` 和 `marketData`，而两者都不注入它。`ctx.watchlist` 继承 `TypertRemoteService`，因此同一个类既是 host 服务又是 `watchlist` Remote 命名空间——这正是 `GoalService` 和 `CommandRuntime` 已经采用的安排，而不是 `PluginInventoryGateway` 因为 Loader 本身不是服务才需要的独立网关。

行是记录的呈现。`followed` 和 `updatedAt` 留在 `ctx.followedNames` 之后：一份关注列表里没有已取消关注的行需要区分，也没有消费方想要最后变更时刻。`displayName` 是记录里的名字而不是 `Quote.name`，因此交易场所给某个上市标的改名不会悄悄重写用户所关注的东西；两者在同一行上传递，并且可以不同。

### 降级的是一行，不是整次调用

报价失败只让它那一行带着 `quote: null`。一份因为某只持仓报不出价就整体消失的自选表，比显示一个短横线更糟，而且那只停止交易的标的通常正是用户在找的。

**选取**提供方的失败是例外，会让整次调用抛出。`MARKET_DATA_PROVIDER_CONFIGURED_MISSING`、`_CONFIGURED_UNAVAILABLE`、`_AMBIGUOUS` 和 `_UNAVAILABLE` 描述的是组合，而不是某个标的：每一行都会以完全相同的方式降级，因此一屏短横线会把一个配置错误的部署呈现为一次安静的数据缺口。其他一切都降级，包括根本不是 `MarketDataError` 的失败——一次 socket 断开说的是这一次调用，而不是这份列表。

### 未上市的代码是取值，不是抛出的错误

`follow` 接收交易场所和代码，读取报价，并记录该场所自己的名称。先读取既证明了该上市标的存在，也提供了浏览器无从知晓的名字。

这个失败返回 `{ ok: false, reason: 'unknown-instrument' }`。网关会把任何抛出的错误压平成只带一条 message 的 `code: 'internal'`，因此抛出式的拒绝会让界面说不出到底出了什么问题——而敲错代码正是用户在那个输入框里最可能做的一件事。其他所有失败仍然抛出，因为它们都不是敲键盘造成的。

两个写操作都打 `new Date().toISOString()`。注册表把时间作为参数，好让它的记录在测试下可复现；本包正是那个知道"用户动作发生在此刻"的调用方，而测试断言的是整条流程而不是那个时刻的取值。

### 标签页放在对话视图环里

`packages/client/ui-watchlist` 以 order 20 注册一个 `conversation.view` 条目，与对话和轨迹并列。该槽位是会话作用域的，而自选表是一本账，在每个会话里都相同；组件不从会话快照读任何东西，因此每个会话显示相同的行。视图环仍然是正确的位置，因为那正是专业用户在"读对话"与"读持仓"之间切换的地方。

每一种状态在记录为空时都有用：空的自选表会说明如何填充它，而不是渲染一个空白面板；报不出价的行显示**无报价**而不是消失。

涨跌方向被表达了三次——文本里的符号、`data-direction` 属性，以及取自主题令牌的颜色——因此一行在灰度、色觉障碍以及读取 DOM 的测试下都成立。红涨绿跌，遵循本产品所服务市场的惯例。

## Alternatives considered

**在 `FollowedNamesService` 上加 `@Remote` 方法，再加一个行情 Remote，由浏览器来连接。** 否决：三十只标的的自选表会变成三十一次往返，而报价正是这一行存在的理由。以 N+1 次线上调用为代价保持两个接缝的纯粹，等于拿用户的延迟去换一个两个接缝都没有要求的抽象。

**在行情接缝上加批量 `quotes(refs[])`。** 目前否决：它会被单一消费方塑形，为包策略所禁止，而且没有第二个调用方。一个有同样需求的持仓界面才是能证成它的东西。

**在 `FollowedNamesService` 上加一个 `watchlist()` 方法并可选注入 `marketData`。** 否决：这与那个包自己写明的立场相矛盾——"渲染自选表的消费方拥有那个表面"——而且会让持久注册表为了回答一个关于记录的问题而依赖行情源。

**让 `unfollow` 返回 `void`。** 否决，改为返回剩余的关注数量：今天浏览器无论如何都会重新加载，但一个计数能让调用方无需第二次往返就完成对账，而一个什么都不返回的 Remote 方法无法告诉客户端状态是否真的变了。

## Consequences

`market-data` 新增了 `./types` 子路径。Typert 要求每一个 Remote 边界类型都能在包根之外被解析到，而 `InstrumentRef` 出现在三个方法签名中的两个里。它的 `files` 列表现在也发布 `lib/types/**/*.js`，因为 `types.ts` 携带 `MarketDataError` 类。

自选表每次挂载或显式刷新才读一次。没有订阅也没有缓存，因此一屏打开着的标签页的新鲜度取决于上一次读取，而三十只标的的列表每次都要付出三十次提供方调用。推送与缓存是各自独立的决定，而且都不是让这个界面可用的前提。

标的只能按代码关注，因为不存在代码检索。在注册表还没有界面时这一点是不可见的；加入表单让它成为用户撞上的第一件事。

一行是数字，不是进入该标的的入口。[工作台设计](../../../../products/chico/workbench-design.md)在详情栏规定的个股档案是下一个界面，在它存在之前该标签页只供阅读，不供导航。

## Testing

`packages/investment/watchlist/tests` 启动真实的注册表、存储与行情组合：连接本身、记录名与场所名的区别、已取消关注记录的省略、空列表、对接缝拒绝与裸 socket 错误两种情况的按行降级、改为抛出的选取失败、由场所解析的显示名、作为取值返回的未上市代码、重新关注时保留的 `firstFollowedAt`、`unfollow` 返回的剩余数量，以及 fiber 拆卸时的服务撤回。

`packages/client/ui-watchlist/tests` 覆盖纯推导（符号、含平盘在内的方向、币种、无报价时的 null、交易场所覆盖、代码规范化）以及在打桩 Remote 之上的视图：有数据的列表、方向属性、幸存的无报价行、空状态、读取失败后的重试、规范化后的关注请求、空代码时禁用的提交、与传输失败相区分的未上市代码提示、关注后的重新加载与字段清空，以及取消关注失败后被点名的那一行——外加视图环注册与 fiber 拆卸证明移除。

`packages/bundle/chico-web-app/tests` 断言发布的 patch 插入了无配置的投影，以及那唯一一行让它可见的浏览器行。
