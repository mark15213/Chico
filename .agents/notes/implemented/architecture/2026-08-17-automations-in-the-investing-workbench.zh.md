# Agent Note: 投资工作台里的自动任务

Status: implemented

[English](2026-08-17-automations-in-the-investing-workbench.md) | 中文

## 问题

工作台回答读者问的问题。读者不看的时候没有任何东西在盯盘，而[工作台设计](../../../../products/chico/workbench-design.md)把监控与提醒推迟了，理由是它需要宿主侧调度。

有两个问题没有答案。**常驻运行的工作放在哪里**——投资栏的三列已经分别被自选名单、一段对话和某只标的的记录占满了？以及**它产出的东西怎么到达读者**——一个盯着 3% 涨幅的专业读者要的是这波怎么回事，不是一条还得自己搬进对话里的通知。

`dsh-schedule` 两个都答不了。它是 Session 作用域的：提醒存在会话日志里，只在那个会话存活时才触发，读者关掉标签页规则就不存在了。而一条关于某只标的的规则，比关于它的每一段对话活得都长。

## 决定

### 规则、命中、投递是三个对象

**规则**不属于任何标的：它带着条件、覆盖范围、节流，以及命中后是否让模型读一段。**命中**属于某一时刻的某一只标的，带着判定条件时所依据的那次观测。**投递**把一次命中放进一段对话。

一条规则覆盖十二只标的，是逐只命中、逐只落地的，所以把三者装进一个对象必然要在其中之一上撒谎。正是这个拆分，让自选行、规则自己的历史、以及 transcript 各取所需。

### 工作台区块承载常驻工作，位于它所作用的名单之上

`investing.workbench.section` 是投资栏在自选名单之上声明的一个 list 插槽。一个条目就是一行、点开一个页面；账本为空时区块连标题都不画，因此没有工作台功能的组合直接从自选名单开始。

区块在名单**之上**而不是并排，因为无人值守运行的东西要先于它所盯的名单被读到，而检索框留在它所检索的名单那一侧。第二个占位者——技能、策略——是一次注册，而不是对 `ui-watchlist` 或 `ui-layout` 的改动。

### 页面接管中间列，但不驱逐对话

`ctx.layout` 新增了 `page`、`openPage`、`closePage`，以及一个渲染在中间列的 root 作用域 keyed `page` 插槽。管理一组规则不是一段对话，也不是某段对话的细节；一组东西需要宽度。

对话在下面**保持挂载并隐藏**，而不是被卸载，因此半句草稿和读者的滚动位置都能熬过一次进出页面。详情列以 `page ?? mode` 为键，因为右列描述的是中间列正在显示的东西——正是[框架模式](2026-08-15-frame-modes-and-name-workbench.md)为框架切换确立的同一条不变式。切换框架会丢弃打开的页面：页面属于提供它的那个框架。

### 条带是钉住的，并且占据自己的高度

`conversation.session.strip` 是位于会话标题栏与 transcript 之间的一个 list 插槽。它是 sticky 的，因此 transcript 滚动时它留在原处；它绘制对话列自身的背景，因此文字从它背后经过而不是穿过它。

它占据自己的高度。一条盖住首个回合的条带，盖掉的正是读者来看的东西。

### 绑定决定对话侧的界面出现在哪里

`ctx.investingFocus` 以只读方式发布打开的标的，因为打开一只标的会移动三列并开启一段对话，这些转换留在工作台手里。

这个选择说的是**框架**正在显示哪只标的，而不是**这段对话**是关于什么的。因此两处对话侧的界面都判定 `focus.sessions.includes(sessionId)`——对话在创建时就绑定到它的标的且永不改绑——这正是工作台图表出于同一原因所做的判定。

### 覆盖范围就是关联，而一只标的可以从两端抵达它

规则通过覆盖范围找到它的标的：全部自选、持仓，或指定标的。持仓经由 `NameStance.posture` 解析，因此一条持仓规则跟随账本、无需维护第二份名单；记录面板补上了这个范围所需的立场编辑器，走的是本就存在却没有界面的 `nameRecord.setStance` 远程调用。

从一只标的出发，`investing.record.section` 和对话条带打开同一个面板，它同时提供两个方向：加入一条指定标的规则，或新建一条只盯这只标的的规则。覆盖全部自选或持仓的规则永远不可加入——它的成员由范围重新算出，手动加进去的标的会与之矛盾。

### 一次投递只有一种渲染

`DeliveredPush` 是推送的唯一组合方式：署名行、观测卡片、作为正文的模型解读、以及追问入口。规则历史里的预览渲染同一个组件，因此预览不可能承诺一种对话拿不到的组合。

卡片不陈述任何模型写下的内容。数字是观测来的，解读是写出来的，把二者混在一起就是把其中之一冒充为另一个。署名行是投递与回答之间的分界：一条没人问就出现、却画得和「回答你刚才的问题」一模一样的推送，会让读者疑惑自己说过什么。

## Alternatives considered

**给自动任务开第三个侧边栏框架，与会话、投资并列。** 否决：它把规则和它们所盯的标的分开了，而这个区块的用意是让常驻工作紧挨着它作用的账本。

**把自动任务做成自选名单里的一个可折叠分组。** 否决：它与名单争夺同一列，且无法扩展到第二个占位者。

**把管理界面放进详情列，或做成全屏弹窗。** 否决：详情列已经承载依据与记录，而一组规则需要宽度；弹窗则把管理一件本就属于工作台的事变成了离开工作台的动作。

**把每次命中都投进一个汇总对话，或每条规则一个对话。** 否决：标的才是工作单元，而一次读者要接着往下问的投递，必须落在那只标的的上下文已经就位的地方。

**让模型解读每一次命中。** 否决：一次全市场异动会让整个账本同时命中，成本和噪声都没有上界。卡片是确定性的、零 token；解读是每条规则自己的选择，默认关闭。

**把条带做成零高度、可点透的浮层。** 否决：它不占高度，于是画在了首个回合上面。

**在对话侧的界面里直接读 `ctx.investingFocus`。** 否决：这个选择是框架状态，于是条带出现在读者打开的每一段对话上，包括关于代码库的那些。

**从标的侧关联时一律新建规则。** 否决：一个条件覆盖十只标的会变成十条规则。

**像 `dsh-schedule` 存提醒那样把规则存进会话日志。** 否决：规则比每一段会话活得都长，而且必须在没有任何会话存活时被求值，因此它的归宿是自选名单旁边的注册表，而不是任何对话的日志。

**让读者为价位突破挑选覆盖范围。** 否决：一个价位只对单只标的成立、对一组不成立，因此编辑器直接固定覆盖范围，而不是接受一条无法成立的规则。

## Consequences

三个共享包获得了新词汇，而它们都不知道自动任务是什么：`ui-layout`（页面）、`ui-conversation`（钉住的条带与 transcript 末尾）、`ui-watchlist`（工作台区块、行标记、记录区块，以及发布出来的选择）。

页面现在同时拥有中间列和右列。这正是让规则的详情不会坐在标的记录旁边的原因，也意味着提供页面的框架必须预期：页面打开期间，它的详情占位者会被替换。

**没有任何规则被求值，也没有任何规则被存储。** 引擎与持久化注册表在宿主侧，尚未构建；规则与命中是编译进 `dsh-client-ui-automation` 的固定数据。每个组件的数据都从 props 进入，因此接线只替换一个模块。管理界面就地写明了这一点，而不是把一条没在运行的规则呈现得像在运行。

**投递还没有进会话日志。** 它搭在 `conversation.chat.foot` 上，因为承载它的会话事件还不存在，所以一次投递无法从日志重建，「模型可见 ⟺ 已记录」这条规则对投递尚未成立。等那个事件落地，投递会移进时间线并按时间穿插。

节流是规则自己的两个字段而不是常量，因为一个在阈值上来回穿越的价格，对读者是一件事、对比较是许多件，而一条规则可以多频繁地说话，是写下它的人做的决定。

`ctx.investingFocus` 是只读的，因此第二个工作台功能可以关于打开的标的，却无法移动它。

## Testing

`packages/client/ui-automation/tests` 覆盖条件、范围、节流三类摘要及其闭合联合的拒绝行为；哪些规则在盯一只标的、哪些命中属于它；卡片作为不含任何written文本的观测；页面的列表、暂停行、选中，以及编辑器对价位突破固定覆盖范围；详情列的事实、覆盖、历史，以及预览就是投递组件本身；条带的已触发与安静两态、它的面板与关联入口；关联面板只提供可编辑覆盖范围的规则、且从不提供该标的已在其中的规则；投递的署名、唯一一份解读与输入框预填；记录区块；以及注册项在 fiber 释放后确实被移除。

两处对话侧界面直接钉住绑定判定：一段不属于打开标的绑定对话列表的对话，既不渲染条带也不渲染投递。

`packages/client/ui-layout/tests` 覆盖 store 里的页面——打开、关闭、每次转换都关闭详情面板、切换框架丢弃页面——以及服务转发与未接线时的响亮失败，还有框架在保持挂载并隐藏的对话之上渲染页面、以页面为键渲染详情、并把打开的页面交给侧边栏。

`packages/client/ui-watchlist/tests` 覆盖工作台区块只在有占位者时出现、在收起的轨道上依然存在、行标记收到该行自己的标的，以及检索框留在自选标题之下。

`packages/bundle/chico-web-app/tests` 断言发布的 patch 把自动任务行插在声明其座位的工作台之后。

## Deferred

- **引擎与注册表** — 条件求值、基于 `Quote.session` 的交易时段闸门、每标的与每规则的节流，以及自选名单旁的持久化规则。
- **投递的会话事件** — 在它存在之前，推送不在日志里，未打开的对话也收不到投递。
- **写操作** — 启用、暂停、新建、关联都只有界面，背后没有对应的操作。
- **三种以外的条件** — 联合是闭合的，第四种条件是一个新成员，而不是既有成员上的一个可选字段。
