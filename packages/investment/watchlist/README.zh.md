# @deepseek-ai/dsh-watchlist

[English](README.md) | 中文

DeepSeek Harness 的自选投影（`ctx.watchlist`）：把[关注标的注册表](../followed-names/README.md)与[行情接缝](../market-data/README.md)的当前报价连接起来，面向浏览器，以 `watchlist` 这个 Typert Remote 命名空间暴露。

## 它是消费方，不是接缝

注册表不知道价格，行情接缝也不知道用户关注了什么。要在一个界面上把名字和价格并排显示就需要两者，因此连接放在本包，而不是放进任何一个接缝——两者都不会因此长出对另一方的依赖，第二个需要同样连接的界面直接复用这一个。

本包返回的行是记录的**呈现**，不是记录本身：`followed` 和 `updatedAt` 留在 `ctx.followedNames` 之后，因为一份关注列表里没有已取消关注的行需要区分，也没有消费方需要最后变更时刻。

## 报不出价的行仍然是一行

报价失败只让它自己那一行降级为 `quote: null`，而不会让整个列表失败。停牌或退市的标的恰恰是用户最需要看到的那一个，而一份因为某只票报不出价就整体消失的自选表，比显示一个短横线更糟。

**选取**提供方的失败是例外，会让整次调用抛出：没有可用提供方、配置的提供方缺失或不可用、以及存在歧义，都是组合错误。这些情况下每一行都会以完全相同的方式降级，因此一屏短横线会把真正的原因伪装成"价格缺失"。

## 检索是标的进入列表的路径

`search` 接收用户输入的内容，返回它所指向的上市标的，并逐条标出是否已经关注。正是这个标志让该操作属于这里而不是行情接缝：一个把已在列表中的标的再次提供为"加入"的选择器，是在请求用户犯错，而只有注册表知道这件事。

调用方传入自己将要绘制的 `limit`，而不是接收本包选定的一个数字，因为渲染列表的那个界面才知道自己能显示多少条。接缝会拒绝任何超过自身上限的取值。

已取消关注的记录会被报告为**未**关注。因此选择器同时也是回到已移出标的的那条路：重新关注会连同原有的 `firstFollowedAt` 一起恢复记录。

## 关注时由交易场所解析名称

`follow` 接收交易场所和代码，读取报价，并记录该场所自己的标的名称。调用方不提供显示名，因为敲下 `SZSE:300750` 的用户并不知道它，而浏览器随便猜一个就会把错误的名字写进持久记录。

先读报价同时也证明了该上市标的存在。这是用户敲键盘最可能造成的失败，因此它以 `{ ok: false, reason: 'unknown-instrument' }` 作为取值返回，而不是抛出错误——RPC 层会把抛出的错误压平成一个不带机器可读原因的内部失败。

两个写操作都打当前时刻。注册表刻意把时间作为参数，好让它的记录在测试下可复现；本包正是那个知道"用户动作发生在此刻"的调用方。

## Model Experience

无，因为该投影在 `ctx.watchlist` 之后服务浏览器界面；它不注册工具、不注入提示词、不写入会话事件。把自选列表呈现给模型的工具拥有那个表面。

#### KV Cache 影响

无；本包从不触及请求前缀。

## Known Limitations and Deferred Work

- **报价每次调用读一次，没有缓存也没有推送。** 浏览器靠再次调用 `list` 刷新，因此一屏打开着的自选表的新鲜度取决于上一次读取，而三十只标的的列表每次都要付出三十次提供方调用。
- **没有面向模型的工具。** 自选表目前只能从界面改动；被要求关注某只标的的 agent 没有任何途径做到，这是该界面的下一块，而不是一个永久的分工。
- **检索沿用提供方的排序，其上没有任何契约。** `search` 原样转发提供方返回的顺序，因此两个提供方对同一查询可以给出不同排序，本包说不出哪一个更好。
- **只有检索能到达已取消关注的记录。** `list` 返回已关注的行，而被移除的标的只能靠再次搜索到达；没有任何途径浏览曾经关注过的东西。
