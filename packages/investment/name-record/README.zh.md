# @deepseek-ai/dsh-name-record

[English](README.md) | 中文

DeepSeek Harness 的标的记录（`ctx.nameRecord`）：用户关于一只标的说过和做过的一切——他持有的立场、支撑它的决策链路，以及绑定到它的对话。

## 记录不依赖自选

用户可以打开任何一只标的、写下一条判断，之后再决定要不要关注它。把记录绑到[关注标志](../followed-names/README.md)上会让"我先看看"变得不可能，也会在有人整理自选表的那一刻删掉一个经过思考的判断。

两者用同一种方式作键（`MARKET:SYMBOL`），因此一只标的的记录和它的关注标志可以由同一个身份寻址，不需要连接表。

## 四种条目，一条链路

**判断**是用户认为什么。**决策**是他做了什么，包括决定不做。**事件**是标的身上发生了什么。**验证**是一条判断后来怎么样了。

种类是封闭的，因为每一种回答不同的问题，而每个界面都要在它们上面分支。条目按最新在前读出；存储时最旧在前，因此追加从不重写数组头部。

**验证是这条链路存在的理由。** 判断和决策业内别处也在记；把一条判断挂起来、等到能结账时回来、并且存下**隔了多久**——这才是校准。`elapsedDays` 是存下来的而不是推导的，因为它是校准数字，不能在重新读取一条记录时发生变化。

验证是唯一会触碰已存储条目的写操作：它恰好结清一条打开的判断，且结论同时落在两边，因此从任一端读这条链路都是一致的。一条判断只回答一次——第二次验证会被拒绝，而不是允许覆盖第一次。

## 来源是必填的

每条条目都说明它从哪来：用户自己写的是 `manual`，来自对话的则记下会话与轮次。一条说不出出处的记录，用户没有理由相信它，而这条链路的全部意义就在于它可审计。

## 立场里的每个数字都由用户手动录入

`posture`（持有 / 观察 / 回避）、`positionPercent` 和 `conviction` 全部属于用户。harness 没有券商连接，而产品猜出来的仓位比它坦承不知道更糟。超出 0–100 的仓位会被拒绝。

`setStance` 保留调用方没有提及的字段，因此编辑一个数字的界面不必复述其余的；`null` 显式清空一个数字。打开一只标的默认为 `watching`，因为打开一只标的并不等于持有它。

## 时间是参数

`append` 和 `setStance` 接收要打的时间戳而不是读时钟，好让校准数字在测试下可复现。`bindSession` 不接收：它记录的是归属，不是时刻。

## Model Experience

无，因为该记录在 `ctx.nameRecord` 之后存储产品状态；它不注册工具、不注入提示词、不写入会话事件。把标的记录呈现给模型的消费方拥有那个表面。

#### KV Cache 影响

无；本包从不触及请求前缀。

## Known Limitations and Deferred Work

- **目前还没有任何东西从对话中提取条目。** 每条条目都由一次显式调用写入，因此实际上全部由用户自己写。自动提取属于记忆系统的设计；本包持有它将要写入的形状，以及它将要填充的来源字段。
- **条目不能编辑也不能删除。** 链路只追加，这对审计轨迹是对的，但也让一个笔误永久留存。纠正需要它自己的决定：是用一条覆盖性条目，还是真正的编辑，才是诚实的模型。
- **事件不携带归因。** 工作台设计把一次涨跌拆成市场、行业和个股特有三部分；这个拆解需要本包没有的数据，因此在归因接缝存在之前，事件只是一段文字。
- **会话绑定是单向的。** 标的能列出它的会话，但会话不知道自己属于哪只标的，因此从会话列表打开的对话显示不出它属于哪个标的。
