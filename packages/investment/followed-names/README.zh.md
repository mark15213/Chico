# @deepseek-ai/dsh-followed-names

[English](README.md) | 中文

DeepSeek Harness 的关注标的注册表（`ctx.followedNames`）：用户关注过的每一个标的的持久记录，以及 Chico 自身工作产物所在的档案目录。

## 取消关注保留记录

`unfollow` 只清除一个标志位，不删除任何东西。笔记、洞察和会话关联都会保留，重新关注会连同原有的 `firstFollowedAt` 一起恢复——记录的年龄取第一次关注，而不是最近一次。对已取消关注的标的再次取消关注会直接返回且不重新打时间戳，因此重复操作既不是错误也不产生写入。

没有删除操作。这是与 harness 现状一致而非发明例外：会话可以归档但不能删除，删除 Workspace 注册也刻意不动它的目录和日志。

记录以标的身份（`MARKET:SYMBOL`）为键，而不是生成的 id，因为标的**就是**身份。重复关注同一个上市标的会就地改名；同一代码在两个交易场所则是两条记录。

## 档案目录

一个目录承载 Chico 自身的工作产物——笔记、模型、调研输出——并且每个 Chico 会话都以它为 cwd 运行，因此产出文件落在持久位置，现有的产出文件界面无需改动即可列出并链接它们。

`archivePath` 默认位于 harness home 之下（`chico/archive`），与 `sessions` 和 `storages` 并列，因为 harness 把所有用户数据放在一个根下。希望目录可见或参与同步的部署把该配置指向别处；相对路径会被拒绝，而不是相对某个环境工作目录解析。

**该目录刻意从不注册为 Workspace。** Workspace 注册表只在一次性引导时收养历史会话，此后仅有 cwd 的会话保持 Ungrouped。因此未注册的目录根本不会产生任何 workspace 行——这正是让用户永远不会看到自己没建过的 workspace 的原因，且不需要隐藏机制，也不需要改动任何持久化格式。

## 时间是参数

`follow` 和 `unfollow` 接收要打的时间戳，而不是读时钟。自己打时间戳的注册表无法针对固定期望断言，而每个调用方本来就知道自己指的是什么时间。

## Model Experience

无，因为该注册表在 `ctx.followedNames` 之后存储产品状态；它不注册工具、不注入提示词、不写入会话事件。把自选列表呈现给模型的消费方拥有那个表面。

#### KV Cache 影响

无；本包从不触及请求前缀。

## Known Limitations and Deferred Work

- **已取消关注的标的只能靠再次搜索到达。** 记录仍在，标的检索会把它标为未关注，因此重新关注能恢复一切；但没有任何界面列出曾经关注过的东西，所以用户一旦忘记代码，那只标的实际上就丢了。
- **会话与标的之间还没有关联。** 记录不携带会话 id，因此"关于这只票的对话"目前无法回答；该关联存放在哪是它自己的一个决定。
- **档案目录内部还没有约定。** 目前没有任何东西规定某只标的的笔记放在其中的什么位置，因此两个消费方可能选择不同布局。
