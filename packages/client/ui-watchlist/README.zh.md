# @deepseek-ai/dsh-client-ui-watchlist

[English](README.md) | 中文

**个股工作台**：Chico 在 harness 框架上增加的两栏。它在侧边栏注册一个导航框架（`sidebar.mode`，id 为 `names`），并注册一个以该框架为键的详情面板（`details`）。切到这个框架时，左栏换成关注的标的，右栏换成打开标的的记录；中栏仍然是对话，由 [ui-conversation](../ui-conversation/README.md) 拥有。

左栏**按关注顺序**列出标的，每行带价格、带符号的涨跌幅，以及当它还有判断没有结清时的标记。按市场决定的任何东西排序，都会让这一列在两次瞥视之间自行重排。列表上方有一个搜索框，按代码或名称检索上市标的；一条匹配可以不关注就直接打开，因此"我先看看"是成立的。

右栏是市场对这只标的说了什么，以及用户对它说过的一切：数字、六十个交易日的图、立场，以及决策链路。条目由用户手写——判断、决策或事件——而一条打开的判断带着结清它的两个按钮。这个结清正是本产品自己的表面：通用 agent 既不保留你的主张，也不会回来给它打分。

## 两栏，两个由插件持有的可观察对象

这批行和打开的标的既不是会话作用域也不是 root 作用域：它们是一本账和一个选择，在每个会话里都相同。槽位的 `store` 句柄只承载一个作用域，而这两个槽位并不共享同一个——侧边栏是 root 作用域，详情栏是会话作用域——因此插件持有这两个值，并把同一份订阅交给两栏。在一栏里关注一只标的会带动另一栏，而在一次读取进行中再请求刷新会加入那一次。

## 涨跌方向被表达了两次

价格方向遵循本产品服务的本地市场惯例——红涨绿跌——通过主题令牌取色，因此两种主题都能正确解析。符号同样写在文本里，方向也放在 `data-direction` 属性上，因此一行在灰度、色觉障碍以及读取 DOM 的测试下都成立。链路条目用同样的方式区分：标记列里的形状，加上日期旁写明的种类。

数字使用等宽数位，好让一列价格对齐；涨跌幅补齐到固定宽度也是同一个理由。

## Model Experience

无，因为本包在 Host 拥有的投影之上渲染浏览器栏位，不注册任何面向模型的内容。

#### KV Cache 影响

无；本包既不组装也不发送提供方请求。

## Known Limitations and Deferred Work

- **中栏还没有按打开的标的收窄**——打开一只标的会移动左右两栏，但中间的对话仍然是当前会话。host 已经记录了哪些对话属于哪只标的，但没有任何东西把它读回框架。
- **没有任何东西从对话中提取条目**——每条链路条目都由用户手写。自动提取，以及让它可撤销的那个回执，属于记忆系统的设计。
- **立场只读不写**——立场、仓位和信心从记录中显示出来，但面板还没有编辑它们的入口，因此在别处设置之前它们保持默认值。
- **事件不携带归因**——设计把一次涨跌拆成市场、行业和个股特有三部分。那需要任何接缝都还没有提供的数据，因此事件只是一段文字。
- **每次挂载只读一次**——两栏都不订阅报价变化，因此一屏打开着的工作台的新鲜度取决于上一次读取。
