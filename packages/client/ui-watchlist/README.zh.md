# @deepseek-ai/dsh-client-ui-watchlist

[English](README.md) | 中文

**投资框架**：Chico 在 harness 框架上增加的东西。它在侧边栏注册一个导航框架（`sidebar.mode`，id 为 `names`，标签为“投资”），注册一个以该框架为键的详情栏（`details`），并注册该框架自己的空白对话开场（`conversation.hero`）。切到这个框架时，左栏换成关注的标的，右栏换成这段对话依据了什么以及打开标的的记录，中栏的开场换成正在谈论的这只标的；对话主体本身仍归 [ui-conversation](../ui-conversation/README.md) 所有。

左栏**按关注顺序**列出标的，每行带价格、带符号的涨跌幅，以及当它还有判断没有结清时的标记。按市场决定的任何东西排序，都会让这一列在两次瞥视之间自行重排。列表上方有一个搜索框，按代码或名称检索上市标的；一条匹配可以不关注就直接打开，因此"我先看看"是成立的。打开的标的会展开它自己的对话列表——"这只票我上周说过什么"的答案在标的旁边，而不是在一个按时间排序的全局列表里。

打开一只标的会移动全部三栏：详情栏被展开，中栏导航到这只标的最新的一次对话，或者打开它的第一次。收起详情栏不会改变已打开的标的和对话；选择或重新选择一只标的会再次展开详情栏。

这里的对话**不属于任何工作区**。它们通过 `sessions.startAt(cwd)` 跑在 [followed-names](../../investment/followed-names/README.md) 的归档目录里，因此产出的文件落在一个持久的地方，而只是随手看了一眼的标的不会留下一个目录。当读者的工作单元是一个项目时，工作区流程是正确的入口；但在一只标的下面，它会挡在读者和他关于这只股票要说的第一句话之间。把它移开的正是本包的 `conversation.hero` 条目：工作区开场在选定项目之前一直让输入框处于禁用状态，而投资开场改为写出标的名称，并让输入框保持可用。

**对话为一只标的而创建，并在创建时就完成绑定。** 没有任何共享，也没有事后认领——读者正在输入的一个未绑定对话，不会被他接下来打开的标的收走，而那正是关于一只股票的对话被归到另一只名下的原因。防止空白对话堆积的复用是按标的进行的，读的是这只标的自己的列表：打开一只标的会回到它最新的一次对话，而在它最新的一次仍是空白时再开新的，则回到那个空白，而不是再加一个。绑定失败丢的是关联，不是对话。

右栏有**两个标签页**。依据在前，因为正在核对一个回答的读者看的是这段对话：对话里的每一个提问，回答都依据了哪些外部来源——某个场所数据源、抓取的某个网页、归档里的某个文件——每一条都写明数据源、数据集、事件时间、采集时刻，以及工具返回的原文。没有依据任何外部数据的回答会明说，因为那个回答是模型自己的。记录则是市场对这只标的说了什么，以及用户对它说过的一切：数字、六十个交易日的图、立场，以及决策链路。条目由用户手写——判断、决策或事件——而一条打开的判断带着结清它的两个按钮。这个结清正是本产品自己的表面：通用 agent 既不保留你的主张，也不会回来给它打分。

详情栏共用的固定标题栏让打开的标的和收起控件在任一标签页滚动时始终可用。两个标签页都保持挂载，未激活的那个是隐藏而不是卸载。每一侧都装着切换不该丢弃的工作：一边是写了一半的链路条目，另一边是已经展开的原文。

## 依据是推导出来的，不会被记录第二遍

没有任何东西去写一份依据日志。这一栏从对话已经有的会话日志推导出来，而"凡是模型可见的都能从日志重建"这条规则，正是让事后归因诚实、而不是在原文旁边另讲一个故事的原因。行情行从行情工具的结果元数据里读出数据源、它的数据集和两个时间事实；网页和归档行读的是调用自己的参数与结果视图。这三类之外的工具不贡献任何一行：这一栏回答的是一个回答依据了什么，而写一条待办是这段对话做过的事，不是它学到的东西。

数据源会说明自己是何时被读取的，而那里的 null 意味着取值是被算出来的而不是采集来的——绝不是当前时钟，因为拿时钟顶替会把生成的数字呈现成抓取来的。网页与归档的读取由 harness 自己执行，因此调用自身的时间就是采集时刻。

## 工作台图表，以及它在哪里生效

图表在价格轴上绘制蜡烛与 MA5/10/20/60，副图可在成交量、MACD（12/26/9）、KDJ（9/3/3）之间切换，十字光标的读数给出光标所在交易日的开、高、低、收、副图自身的数值，以及每一条均线的值。参数沿用境内行情软件的出厂设置——一个改了参数的工作台会让每一个读数都无法与用户已经在读的平台对照。左右方向键逐日移动光标；标题价格是一个 `<output>`，因此数值变化会被读屏播报，而不是无声改变。

图表按**实测像素宽度**绘制，绝不拉伸 viewBox：蜡烛比例、标签字号和线宽在任何容器宽度下都保持不变。指标在整条序列上计算、之后才切到可见窗口——若在切片上计算，每次预热都会从左边缘重新开始，同一个交易日的 MA60 会随着缩放程度而改变。价格范围会被撑开以容纳可见的均线，否则 MA60 会画到绘图区外面。

图表出现在两个地方，其中第二处通过 [ui-tool](../ui-tool/README.md) 的 `tool.call.priceSeries` 座位接入：

| 位置 | 绘制什么 |
|---|---|
| “记录”标签页 | 打开标的时显示这张图。 |
| 对话中的 `market_history` 调用 | 对话**绑定到某只标的**时是这张图，否则是出厂的 `PriceSeriesBlock`。 |

判据是绑定关系而不是当前 frame。对话在创建时绑定且永不改判，因此读者切换 frame 不会改变一段对话里图表的形态——而挂载 Chico 也不会改变一段关于代码库的对话里价格序列的样子。

## 两栏，两个由插件持有的可观察对象

这批行和打开的标的既不是会话作用域也不是 root 作用域：它们是一本账和一个选择，在每个会话里都相同。槽位的 `store` 句柄只承载一个作用域，而这两个槽位并不共享同一个——侧边栏是 root 作用域，详情栏是会话作用域——因此插件持有这两个值，并把同一份订阅交给两栏。在一栏里关注一只标的会带动另一栏，而在一次读取进行中再请求刷新会加入那一次。

## 涨跌方向被表达了两次

价格方向遵循本产品服务的本地市场惯例——红涨绿跌——通过主题令牌取色，因此两种主题都能正确解析。符号同样写在文本里，方向也放在 `data-direction` 属性上，因此一行在灰度、色觉障碍以及读取 DOM 的测试下都成立。链路条目用同样的方式区分：标记列里的形状，加上日期旁写明的种类。

数字使用等宽数位，好让一列价格对齐；涨跌幅补齐到固定宽度也是同一个理由。

## Known Limitations and Deferred Work

- **没有任何东西从对话中提取条目**——每条链路条目都由用户手写。自动提取，以及让它可撤销的那个回执，属于记忆系统的设计。
- **立场只读不写**——立场、仓位和信心从记录中显示出来，但面板还没有编辑它们的入口，因此在别处设置之前它们保持默认值。
- **事件不携带业绩归因**——设计把一次涨跌拆成市场、行业和个股特有三部分。那需要任何接缝都还没有提供的数据，因此事件只是一段文字。依据栏归因的是来源，那是另一个问题。
- **依据落到回答一级，不到论断一级**——这一栏说的是一个回答依据了哪些来源，不是哪一句话依据哪一个来源。把一句话系到一个来源上，需要模型自己给出引用。
- **依据止于已加载的窗口**——尚未加载的更早轮次不贡献任何东西，而提问落在窗口之外的来源会归到一个没有标题的问答下，而不是被丢弃。
- **每次挂载只读一次**——各栏都不订阅报价变化，因此一屏打开着的工作台的新鲜度取决于上一次读取。
- **对话不知道自己属于哪只标的**——绑定是单向的，因此从会话框架打开的对话不会显示它属于哪个标的。
- **图表既不能缩放也不能平移**——窗口只有五个预设区间。滚轮缩放和拖拽平移需要一套预设列表所没有的视口模型。
- **绑定到未被打开的标的的对话仍绘制出厂蜡烛图**——占座判断依据的是当前打开标的的对话列表，因此从会话框架回看一段已绑定的对话、而没有先打开它对应的标的时，看到的是紧凑图表。
- **副图只有三个指标，且没有主图叠加线**——没有布林带，没有成交量加权均价，也没有从配置里加一条的办法。
