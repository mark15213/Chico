# @deepseek-ai/dsh-client-ui-automation

[English](README.md) | 中文

**投资工作台里的自动任务**：无人值守盯盘的规则、管理它们的地方，以及某条规则成立时它说的话。它把工作台区块的第一个占位者注册进 [ui-watchlist](../ui-watchlist/README.md) 的 `investing.workbench.section`，把管理页面注册进 [ui-layout](../ui-layout/README.md) 的 `page` 座位并带上它的详情列，另外还有三处关于某一只标的的界面——对话之上的条带、对话之内的投递、标的记录里的区块，以及自选行上的标记。行为规格见[自动任务 Agent Note](../../../.agents/notes/implemented/architecture/2026-08-17-automations-in-the-investing-workbench.md)。

**没有任何规则被求值，也没有任何规则被存储。** 规则与它们的命中是编译进本包的固定数据（`src/client/fixture.ts`）：判定条件的引擎与持有规则的持久化注册表都在宿主侧，尚未构建。每个组件的数据都从 props 进入，因此接线只替换那一个模块，本包其余部分不变。管理页面就地写明了这一点，因为一条没在运行的规则不能被呈现得像在运行。

## 规则、命中、投递

**规则**不属于任何标的：条件、覆盖范围、节流，以及命中后是否让模型读一段。**命中**属于某一时刻的某一只标的，带着判定条件时所依据的那次观测。**投递**把一次命中放进一段对话。

一条规则覆盖十二只标的，是逐只命中、逐只落地的，所以把三者装进一个对象必然要在其中之一上撒谎。正是这个拆分，让自选行、规则自己的历史、以及 transcript 各取所需。

条件是一个闭合联合——日内涨跌幅、滚动窗口内的变动、价位突破——因此第四种条件是一个新成员，而不是既有成员上的一个可选字段。价位突破只对单只标的成立、对一组不成立，因此选中它会固定覆盖范围，而不是接受一条无法成立的规则。

节流是规则自己的两个字段而不是常量：同一只标的多久之后才可以再次触发，以及这条规则一天最多投递多少条。一个在阈值上来回穿越的价格，对读者是一件事、对比较是许多件，而一条规则可以多频繁地说话，是写下它的人做的决定。

## 覆盖范围就是关联，且可以从两端抵达

规则通过覆盖范围找到它的标的：全部自选、持仓，或指定标的。持仓经由标的记录的 `posture` 解析，因此一条持仓规则跟随账本、无需维护第二份名单。

从一只标的出发，记录区块和对话条带打开同一个面板，它同时提供两个方向：加入一条指定标的规则，或新建一条只盯这只标的的规则。覆盖全部自选或持仓的规则永远不可加入——它的成员由范围重新算出，手动加进去的标的会与之矛盾。只提供新建，会把一个覆盖十只标的的条件变成十条规则。

## 绑定决定对话侧的界面出现在哪里

`ctx.investingFocus` 说的是投资**框架**正在显示哪只标的，而不是**这段对话**是关于什么的。因此条带与投递都判定当前会话是否属于打开标的的绑定对话；对话在创建时就绑定到它的标的且永不改绑。直接读这个选择，会让条带出现在读者打开的每一段对话上，包括关于代码库的那些。这正是[工作台图表](../ui-watchlist/README.md)出于同一原因所做的判定。

## 一次投递只有一种渲染

`DeliveredPush` 是推送的唯一组合方式：署名行、观测卡片、作为正文的模型解读，以及预填输入框的追问入口。规则历史里的预览渲染同一个组件，因此预览不可能承诺一种对话拿不到的组合。

卡片不陈述任何模型写下的内容。数字是观测来的，解读是写出来的，把二者混在一起就是把其中之一冒充为另一个。署名行把投递与回答分开：一条没人问就出现、却画得和「回答你刚才的问题」一模一样的推送，会让读者疑惑自己说过什么。

只要有规则在盯这只标的，条带就一直可见，在有触发之前是淡的。什么在运行，值得在它开口之前就知道；而一个只在命中之后才出现的控件，回答不了「现在有东西在盯吗」。

## Model Experience

None, as this package renders browser surfaces over rules it does not own and touches no prompt, message, schema, stream, or tool result.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **什么都没在跑** — 没有条件被求值，没有规则被存储，也没有命中被产生。引擎、它的交易时段闸门、它的节流，以及自选名单旁的持久化注册表全部缺席，因此这些界面上的每一个数字都来自编译进来的固定数据。
- **投递不在会话日志里** — 它搭在 `conversation.chat.foot` 上，因为承载它的会话事件还不存在。因此一次投递无法从日志重建，模型也读不到在它作答的那个回合之前抵达的投递，而未打开的对话什么都收不到。等那个事件落地，投递会移进时间线并按时间穿插。
- **每一个写操作都只有界面没有操作** — 启用、暂停、新建、关联都会渲染和校验，然后什么也不做。
- **规则的覆盖范围是替它算好的** — 固定数据里直接带着每条规则当前覆盖的标的。本包不解析自选范围也不解析持仓范围，因此这些界面显示的数量并非从它们所称的注册表推导而来。
