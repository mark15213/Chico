# 投资领域模型

本文建立产品文档使用的初始领域词汇。它不是数据库 schema，也不替代具体能力的类型和 API 设计。

## 核心实体

| 实体 | 含义 | 必须保留的身份或时间信息 |
|---|---|---|
| 标的 | 可研究、持有或交易的证券、合约、指数或其他金融对象 | 稳定标识、市场、币种、有效期 |
| 数据观察值 | 某一来源在特定时间提供的市场或基本面值 | 来源、事件时间、采集时间、单位、调整方式 |
| 研究来源 | 支持或反驳投资判断的原始材料 | 发布者、发布时间、获取时间、许可和内容身份 |
| 投资观点 | 对标的、主题或事件的可检验判断 | 作者、论据、反证条件、有效期限、版本 |
| 组合 | 在授权范围内管理的一组资产和现金关系 | 账户范围、基准、币种、估值时间 |
| 持仓 | 组合对标的的数量、成本和风险暴露 | 组合、标的、数量、估值时间、数据来源 |
| 授权约束 | 限定可持有、可建议或可执行行为的规则 | 适用主体、范围、生效时间、批准来源 |
| 情景 | 用于估计组合或观点结果的一组明确假设 | 假设集、时间范围、模型版本、输入版本 |
| 建议 | agent 或用户提出、尚未获得执行权的行动主张 | 提出者、证据、时间、适用组合、审批状态 |
| 订单意图 | 已结构化但尚未提交外部执行系统的交易请求 | 授权链、标的、方向、数量或目标、有效期限 |

## 关系原则

研究来源支持或反驳投资观点；投资观点和情景可以产生建议；建议只有在满足授权约束并经过所需人工确认后才能形成订单意图。订单意图不是成交，外部执行结果也不能由 agent 的文字声明代替。

## 待决领域问题

- 多资产类别是否共享同一标的和订单意图模型？
- 组合、账户、策略和授权委托之间采用什么身份关系？
- 公司行动、复权、币种转换和基准数据由哪个能力负责？
- 研究观点如何版本化、失效和被后续证据推翻？
